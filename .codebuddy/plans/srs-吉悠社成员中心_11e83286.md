## 需求概述

基于已评审通过的《PRD-吉悠社成员中心》v1.0（Q1–Q8 已全部闭环回填），编写《软件需求规格说明书（SRS）》，作为后续概要设计、详设、开发与测试的依据。

**新增变更（2026-09-30 需求方确认）**：账号体系新增"等级与经验值系统"，涉及 PRD C5/Q5 变更与新增功能，SRS 纳入并回写 PRD v1.1。

## 产品概述

"吉悠社成员中心"是一个面向综合游戏兴趣社群的 Web 平台，包含账号与会员体系、论坛、成员、活动、后台管理、通知六大模块，五级角色体系（游客/普通成员/版主/活动组织者/管理员），覆盖"游客浏览→注册入会→论坛互动→活动报名"最小闭环及完整运营治理能力。

## 新增：等级与经验值系统（需求方 2026-09-30 确认口径）

| # | 确认项 | 结论 |
| --- | --- | --- |
| N1 | 等级依据 | **等级由经验值决定**；赛事积分仍独立累积为贡献值展示，但不再决定等级（PRD C5/Q5 变更，需回写 PRD） |
| N2 | 经验值获取渠道 | ①新增**每日签到**功能（每日一次得经验，PRD 无此功能，属新增项）；②**活动结束后统一发放奖励（经验值+积分）**；③管理员赠送 |
| N3 | 管理员赠送 | 管理员可向成员赠送经验值和积分，赠送后**通知成员**（站内）；操作留痕（对齐 R8/E11） |
| N4 | 优先级 | **P1（首发完整体验）**（PRD C5 原为 P2，随本次变更上调） |
| N5 | 数值与规则 | 经验值获取数值、等级档位表、赠送上限等**全部后台可配置**（对齐 R9）；默认值待运营方确认，列入待确认清单 |
| N6 | 权限原则 | 等级仅荣誉展示，**不解锁任何权限**（保留 Q5 原则） |


新增 SRS 需求编号：FR-G1 每日签到、FR-G2 经验值与等级（含活动结束统一发放奖励）、FR-G3 管理员赠送经验值/积分（含通知）。活动奖励发放口径：活动结束后按出勤（签到）记录统一发放，仅出席者获得奖励；发放触发方式等细则列入待确认清单。

**PRD 回写项（v1.1，随 SRS 交付同步执行）**：

1. C5 改写：等级由经验值决定，贡献值（赛事积分累积）仅展示；

3. 5.4 D5 补充"活动结束后统一发放奖励（经验+积分）"；
4. 5.6 F1 通知覆盖范围补充"经验值/积分变动通知"；

6. 变更记录表新增 v1.1 条目，标注来源"需求方 2026-09-30 确认"。

## 核心交付内容

1. **功能需求逐条展开**：将 PRD 5.1–5.6 共 53 个功能条目（A1–A8、B1–B15、C1–C5、D1–D10、E1–E11、F1–F4）逐条展开为结构化软件需求，另展开新增 G 模块 3 条（FR-G1–FR-G3，标注"PRD 变更项"），每条包含：功能描述、输入、输出、业务规则（含 R1–R10 与 Q8 的 25 条运营参数默认值）、异常分支、权限要求，并标注 PRD 章节号实现双向可追溯；
2. **非功能需求**：性能指标（NF1–NF3）、可用性（NF4）、并发预估（≤5000 成员、峰值在线 ≤500，压测校准）、安全要求（NF5–NF10）、兼容性范围（Web 响应式，X2）、数据备份策略、合规要求（NF11–NF15）；
3. **角色-权限矩阵**：基于 PRD 3.2 复核并细化，补充新增项（每日签到=普通成员、管理员赠送=管理员）；
4. **状态机定义**：核心业务对象（用户账号、入会申请、帖子/回帖内容、举报工单、活动、报名/候补记录、组队、赛事）状态机；补充**经验值/积分账务流水模型**（获取/赠送/活动发放三类来源，只增不减）；
5. **概念数据模型**：实体与关系 ER 图（不落表结构），新增实体：每日签到记录、经验值流水、积分流水、等级档位配置；
6. **可追溯性矩阵**："PRD 功能编号 ↔ SRS 需求编号"双向追溯表，PRD 53 条覆盖率 100%，新增 G 模块单列并标注 PRD 变更状态；
7. **待确认清单**：PRD 未定义项（数据备份策略、浏览器最低版本、人工审核队列时效）+ 新增项（经验值/等级数值默认值、活动奖励发放触发细则、每日签到连续奖励规则等）上报，不自行扩展。

### 编写规范

- 需求编号规则：`FR-<模块字母><序号>`（如 FR-A1、FR-G1），NFR 编号沿用 `NFR-x`；每条需求头部标注来源（PRD 章节 + Q 编号，G 模块标注变更确认来源）；
- 功能需求统一模板：功能描述 / 优先级 / 输入 / 输出 / 业务规则 / 异常分支 / 权限要求 / 关联流程 / 关联状态机；
- 运营参数（R9）统一以"默认值 + 可配置"格式表述，并在附录汇总为参数表；
- 状态机使用 mermaid stateDiagram，实体关系使用 mermaid erDiagram；
- 严格对齐 PRD：已确认内容展开细化（输入输出与异常分支属需求工程合理细化，不新增业务规则）；PRD 未定义处一律列入第 9 章待确认清单。
